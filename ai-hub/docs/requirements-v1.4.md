# v1.4 需求文档 — 生成结果修复与序列任务调度

> 版本：v1.4 · 日期：2026-10-18 · 状态：已交付（Loop Engineering 全流程验证通过）
> 关联：[spec-v1.4-generation-sequence.md](./spec-v1.4-generation-sequence.md)（技术规格）、[technical-v1.4.md](./technical-v1.4.md)（技术文档）、[user-guide.md](./user-guide.md)（操作说明）

## 1. 背景与问题

v1.3 之前的「AI 智能测试」模块在真实使用中暴露出**生成结果缺失**与**执行不可控**两大类问题：

| # | 问题现象 | 影响 |
|---|---------|------|
| P1 | 点击生成后任务直接 500 / 无流式输出 | 功能不可用 |
| P2 | 任务显示"完成"但生成记录里用例数为 0 | 结果缺失，无法追溯 |
| P3 | 生成完成的用例无法保存到用例库（422） | 结果无法沉淀 |
| P4 | 后端重启后任务永远停留在"执行中"（僵尸任务） | 状态失真 |
| P5 | 评审 / 定时任务端点偶发 500（NameError） | 关联功能不可用 |
| P6 | 长需求只能一次性生成，无法按模块拆分 | 粒度粗、质量差 |
| P7 | 免费模型（本地/低配额）与付费模型共用同一并发策略 | 免费模型被打挂，付费模型吞吐浪费 |
| P8 | 定时任务"执行"只写日志不产生任何真实结果 | 形同虚设 |

## 2. 需求清单

### R1 生成链路修复（P1–P5）— 必须
- R1.1 单任务四步工作流（分析→编写→评审→修订）全链路 SSE 流式输出，前端可见 token 流；
- R1.2 生成结果用例数真实统计并展示（来自结构化解析，而非估算）；
- R1.3 「采用 → 保存到用例库」闭环可用：候选用例支持逐条采用，保存后进入用例库并关联项目；
- R1.4 后端启动时自动回收中断任务（置为可重跑状态），不再出现僵尸"执行中"；
- R1.5 评审创建、定时任务等端点在匿名/登录两种态下均稳定（统一 `get_optional_user`）。

### R2 生成序列调度（P6、P7）— 核心新增
- R2.1 长需求按 Markdown 标题（`#`/`##`）自动拆分为 N 个子任务，形成有序序列；
- R2.2 **免费模型 → 单任务序列**：并发 1，严格按 `seq_index` 逐个执行（保护免费配额）；
- R2.3 **付费模型 → 并行序列**：默认最多 3 个子任务并行（环境变量可调），槽位可视化；
- R2.4 序列详情页按编号顺序循环渲染每个子任务的 4 步进度（卡片 + 步骤条）；
- R2.5 序列支持整体取消、失败子任务一键重跑；
- R2.6 模型列表返回 `tier`（free/paid）与调度提示，前端选择器直接展示「·免费/·付费」。

### R3 定时任务真实执行（P8）
- R3.1 定时任务可关联项目、指定模型、配置需求文本；cron 到点自动创建真实生成任务；
- R3.2 执行日志记录真实状态、耗时、结果摘要（生成 N 条用例）与 exec_ref（可跳转任务详情）。

### R4 离线可验证性
- R4.1 无任何 LLM API Key 时，平台全流程（生成/评审/修订/序列/定时）可完整跑通——内置确定性 `mock` provider（`mock:mock-demo` 免费 / `mock:mock-pro` 付费），用于演示、CI 与验收。

## 4. 非功能约束
- 免费模型识别优先级：环境变量 `FREE_MODEL_IDS` > 模型表 `tier` 标注 > `provider=ollama` 兜底；
- 并行上限 `SEQUENCE_MAX_PARALLEL_PAID` 默认 3，可按账号配额调整；
- 所有新环境变量必须在 `config.Settings` 中声明（extra=forbid）；
- 后台协程（序列调度、定时执行、生成）禁止复用请求级数据库连接，必须自取连接并显式提交。
